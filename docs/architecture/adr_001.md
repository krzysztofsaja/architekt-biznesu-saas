# ADR 001: Wybór Supabase jako backend

## Status
Zaakceptowany

## Kontekst
Potrzebowaliśmy rozwiązania backendowego dla aplikacji Smieciarka, które zapewni:
- Bazę danych relacyjną
- Uwierzytelnianie użytkowników
- Magazynowanie plików (zdjęcia przedmiotów)
- Subskrypcje w czasie rzeczywistym (dla czatu)
- Szybkie wdrożenie bez konieczności zarządzania serwerem

## Rozważane opcje
1. **Tradycyjny backend** (Node.js/Express + PostgreSQL)
   - Wymagałoby zarządzania serwerem, skalowaniem, utrzymaniem
   - Więcej kontroli, ale większy wysiłek rozwojowy
   
2. **Firebase**
   - Dobra integracja z Google usługami
   - Ograniczenia w zapytaniach NoSQL
   - Koszty mogą rosnąć przy większej liczbie użytkowników
   
3. **Supabase** (wybrane)
   - Open-source alternatywa dla Firebase
   - Pełna PostgreSQL pod spodem
   - Built-in auth, storage, realtime subscriptions
   - Darmowy wystarczający dla MVP
   - Łatwe migracje SQL

## Decyzja
Wybraliśmy Supabase ze względu na:
- Połączenie mocy PostgreSQL z prostotą użycia
- Wbudowane funkcje potrzebne dla naszej aplikacji (auth, storage, realtime)
- Darmowy plan wystarczający dla etapu rozwoju i testów
- Możliwość samodzielnego hostowania w przyszłości jeśli będzie potrzebne
- Dobra dokumentacja i biblioteki klienckie

## Konsekwencje
### Pozytywne
- Szybszy rozwój początkowy
- Mniej infrastruktury do zarządzania
- Wbudowane zabezpieczenia (RLS - Row Level Security)
- Łatwe skalowanie w ramach planów Supabase

### Negatywne
- Uzależnienie od zewnętrznego dostawcy
- Mniejsza kontrola nad optymalizacją bazy danych niż w przypadku själv zarządzanego PostgreSQL
- Ograniczenia w niektórych zaawansowanych funkcjach PostgreSQL w zależności od planu

## Implementacja
- Używamy `@supabase/supabase-js` jako klienta
- Konfiguracja poprzez zmienne środowiskowe: `VITE_SUPABASE_URL` i `VITE_SUPABASE_PUBLISHABLE_KEY`
- Wykorzystujemy Row Level Security (RLS) dla kontrolowania dostępu do danych
- Korzystamy z Supabase Storage dla przechowywania zdjęć przedmiotów
- Używamy realtime subscription dla funkcji czatu
