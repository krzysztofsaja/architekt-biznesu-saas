# ADR 002: Wybór stosu technologicznego frontendowego

## Status
Zaakceptowany

## Kontekst
Potrzebowaliśmy stworzyć responsywną aplikację webową z mapami, formularzami i czatem, która będzie:
- Szybka w ładowaniu i responsywna
- Łatwa w utrzymaniu i rozwijaniu
- Kompatybilna z urządzeniami mobilnymi i desktopowymi
- Wdrożona szybko dla MVP

## Rozważane opcje
1. **Vanilla HTML/CSS/JS**
   - Maksymalna kontrola, ale znacznie więcej kodu pisania ręcznego
   - Wolniejsze tempo rozwoju
   
2. **Vue.js**
   - Dobra dokumentacja, łagodna krzywa uczenia się
   - Mniejsza społeczność niż React
   
3. **React** (wybrane)
   - Duża społeczność i ekosystem
   - Wielu dostępnych bibliotek i komponentów
   - Dobra wydajność dzięki wirtualnemu DOM
   - JSX pozwala na mieszanie logiki i prezentacji
   
4. **Angular**
   - Pełne framework, ale bardziej ciężki
   - Steep learning curve
   - Więcej kodu boilerplate

## Decyzja
Wybraliśmy React 18 z Vite ze względu na:
- Ekosystem bogaty w biblioteki (Leaflet dla map, różne komponenty UI)
- Szybkie odświeżanie podczas rozwoju dzięki Vite
- Duża dostępność tutoriali i pomocy społecznościowej
- Kompatybilność z Tailwind CSS dla utility-first stylowania
- Możliwość stopniowego przyjęcia (można zacząć od prostych komponentów)

## Rozważania dotyczące dodatkowych technologii
- **Vite** jako narzędzie budujące zamiast Webpack dla szybszego uruchamiania i budowania
- **Tailwind CSS** dla stylowania utility-first zamiast tradycyjnego CSS lub frameworków jak Bootstrap
- **Leaflet.js** dla map ze względu na prostotę, darmowość i otwartość (alternatywa dla płatnego Google Maps)
- **Dexie.js** jako wrapper dla IndexedDB do lokalnego cache'u dla trybu offline

## Konsekwencje
### Pozytywne
- Szybkie prototypowanie dzięki gotowym rozwiązaniom
- Dobra wydajność aplikacji
- Łatwe znalezienie deweloperów Reacta na rynku pracy
- Modułowa struktura umożliwiająca łatwe dzielenie pracy

### Negatywne
- Konieczność nauki JSX dla członków zespołu niezaznajomionych z Reactem
- Konfiguracja stanu aplikacji może wymagać dodatkowych bibliotek (jest w planach użycie Context API lub Redux dla bardziej złożonych stanów)
- Rozmiar paczki może być większy niż w przypadku czystego Vanilla JS (zarządzany przez code splitting i lazy loading)

## Implementacja
- React 18 jako główna biblioteka UI
- Vite jako narzędzie budujące i development server
- Tailwind CSS dla stylowania z konfiguracją w `tailwind.config.js` i `postcss.config.js`
- Leaflet.js poprzez react-leaflet dla integracji z Reactem
- Dexie.js dla lokalnego cache'u danych
- React Router (w planach) dla nawigacji między widokami
